# Подготовка к защите лабораторной работы №1

## Тема проекта

Трекер лабораторных работ и домашних заданий. Сервис должен помогать студенту следить за публикациями, заданиями, расписанием, планом работы и уведомлениями.

В первой лабораторной сделан frontend-каркас. Данные пока демонстрационные и хранятся в коде или состоянии React.

## Экраны приложения

| URL | Компонент | Что показывает |
|---|---|---|
| `/` | `Dashboard` | Ленты публикаций и статистику |
| `/tasks` | `Tasks` | Задания и форму добавления |
| `/schedule` | `Schedule` | Ближайшие задания как расписание |
| `/planner` | `Planner` | План работы на неделю |
| `/notifications` | `Notifications` | Список уведомлений |

## Общий алгоритм работы

```text
index.html
  ↓ подключает
src/main.tsx
  ↓ подключает библиотеки и создаёт приложение
BrowserRouter
  ↓ передаёт текущий URL
Layout
  ↓ показывает навигацию и выбирает маршрут
нужный компонент страницы
  ↓ возвращает JSX
React
  ↓ превращает JSX в HTML
браузер
```

При клике по навигации `NavLink` меняет URL без полной перезагрузки. `Routes` видит новый URL и выбирает соответствующий `Route`. Например, адрес `/tasks` приводит к вызову компонента `Tasks`.

## Взаимодействие компонентов

```text
Layout
└── Routes
    ├── Dashboard
    │   └── TaskList
    ├── Tasks
    │   └── TaskListOverride
    ├── Schedule
    │   └── TaskListOverride
    ├── Planner
    └── Notifications
```

`Layout` — родительский общий каркас. `Routes` выбирает одну страницу. `Dashboard` и `Schedule` используют готовый список, а `Tasks` дополнительно управляет состоянием и передаёт изменяемый список в `TaskListOverride`.

## Разбор `main.tsx` по порядку

### 1. Импорты

```tsx
import { StrictMode, useState } from "react";
import { createRoot } from "react-dom/client";
```

`import` подключает готовые возможности из пакетов. `useState` нужен для хранения текста поля и списка заданий. `createRoot` нужен, чтобы подключить React к HTML-элементу `root`. `StrictMode` включает дополнительные проверки React в development-режиме.

```tsx
import { BrowserRouter, NavLink, Route, Routes, useNavigate } from "react-router-dom";
```

`BrowserRouter` даёт компонентам доступ к маршрутизации. `NavLink` — ссылка с информацией об активном маршруте. `Routes` выбирает маршрут, `Route` описывает соответствие URL и компонента. `useNavigate` возвращает функцию для перехода из обработчика.

Импорты из `@mui/material` — готовые UI-компоненты. Например, `Card` создаёт карточку, `Typography` выводит текст, `Stack` располагает элементы, а `TextField` создаёт поле ввода.

### 2. Тема

```tsx
const theme = createTheme({
  palette: { primary: { main: "#4255d4" } },
  shape: { borderRadius: 8 },
});
```

`createTheme` создаёт общий объект настроек Material UI. В нём задаются основной цвет и радиус скругления. Позже объект передаётся в `ThemeProvider`, чтобы все UI-компоненты использовали одинаковую тему.

### 3. Тип и демонстрационные данные

```tsx
type Task = { title: string; course: string };
const tasks: Task[] = [
  { title: "Лабораторная работа №1", course: "Frontend" },
];
```

`Task` — тип одного задания. У него есть строковое название и строковый канал/курс. `Task[]` означает массив таких объектов. Массив используется как начальное содержимое интерфейса вместо запроса к backend.

## Компонент `Layout`

### Назначение

`Layout` — общий родительский компонент. Он отображает верхнюю панель на всех страницах и содержит место для текущего экрана.

### Навигация

```tsx
[
  ["/", "Ленты"],
  ["/tasks", "Задания"],
  ["/schedule", "Расписание"],
  ["/planner", "Планер"],
  ["/notifications", "Уведомления"],
].map(([to, label]) => (
  <Button component={NavLink} to={to} key={to}>
    {label}
  </Button>
))
```

Здесь хранится массив маршрутов. Каждая пара состоит из адреса и видимого названия.

`.map` — метод массива. Он по очереди берёт элементы, передаёт каждый в функцию и собирает возвращённые результаты в новый массив. В этом месте результатом является массив кнопок.

Для пары `["/tasks", "Задания"]` создаётся:

```tsx
<Button component={NavLink} to="/tasks" key="/tasks">
  Задания
</Button>
```

`[to, label]` — деструктуризация пары: адрес записывается в `to`, подпись — в `label`. `to={to}` передаёт адрес `NavLink`, а `{label}` выводит текст.

`component={NavLink}` означает, что внешне используется кнопка Material UI, но переход выполняется как у React Router-ссылки. `key={to}` нужен React для отслеживания элементов, созданных через `.map`.

### Верхняя панель и маршруты

`AppBar` создаёт верхнюю панель. `Toolbar` ограничивает и центрирует её содержимое. `Stack direction="row"` располагает кнопки в одну строку.

```tsx
<Container maxWidth="lg" sx={{ py: 4 }}>
  <Routes>
    <Route path="/" element={<Dashboard />} />
    <Route path="/tasks" element={<Tasks />} />
    <Route path="/schedule" element={<Schedule />} />
    <Route path="/planner" element={<Planner />} />
    <Route path="/notifications" element={<Notifications />} />
  </Routes>
</Container>
```

`Container` задаёт область основного содержимого. `Routes` сравнивает URL с `path`. Если путь `/tasks`, отображается `Tasks`; если `/planner`, отображается `Planner`.

## Компонент `Dashboard`

### Общая логика

`Dashboard` — экран, который пользователь видит по адресу `/`. Он показывает заголовок, три карточки со статистикой, последние публикации и кнопку перехода ко всем заданиям.

```tsx
const nav = useNavigate();
```

`useNavigate` возвращает функцию перехода. Она сохраняется в переменной `nav` и вызывается при клике на «Все задания».

### Статистика

Массив содержит пары: число и подпись. `.map` превращает каждую пару в `Card`.

```text
["3", "Новых публикации"]
  ↓
Card с числом 3 и подписью «Новых публикации»
```

`CardContent` задаёт внутреннее содержимое карточки. `Typography` показывает `n` и `t`. `flex: 1` позволяет карточкам занимать одинаковую ширину.

### Переход к заданиям

```tsx
<Button color="inherit" onClick={() => nav("/tasks")}>
  Все задания
</Button>
```

`onClick` — обработчик клика. После клика вызывается `nav`, URL меняется на `/tasks`, затем `Routes` показывает компонент `Tasks`.

### Вызов списка

```tsx
<TaskList />
```

React вызывает `TaskList` и вставляет его результат в это место. `Dashboard` не передаёт список через prop, поэтому `TaskList` использует общий массив `tasks`.

## Компонент `TaskList`

### Назначение

`TaskList` только отображает исходные демонстрационные задания. У него нет `useState`, поля ввода и обработчиков изменения.

```tsx
tasks.map((task, i) => (
  <ListItem key={task.title} divider={i < tasks.length - 1}>
    <ListItemText primary={task.title} secondary={task.course} />
  </ListItem>
))
```

На каждой итерации `task` — текущий объект, `i` — его индекс. `task.title` передаётся в основной текст, `task.course` — в дополнительный.

`divider` получает результат сравнения `i < tasks.length - 1`. Поэтому разделитель есть у всех элементов, кроме последнего.

`TaskList` вызывается из `Dashboard`. После завершения он возвращает `Card` со списком, и `Dashboard` вставляет эту карточку в свой JSX.

## Компонент `Tasks`

### Назначение

`Tasks` — экран `/tasks`. Он показывает форму и изменяемый список. Это единственный экран, где пользователь может добавить новое задание.

### Состояние

```tsx
const [title, setTitle] = useState("");
const [shown, setShown] = useState(tasks);
```

`useState` возвращает пару: текущее значение и функцию его изменения.

- `title` — текст в поле ввода;
- `setTitle` — изменить текст;
- `shown` — список, который нужно показать;
- `setShown` — изменить список.

Начальное значение `title` — пустая строка, начальное значение `shown` — массив `tasks`.

Обычная переменная не подошла бы для `shown`: React не узнал бы об изменении и не перерисовал список. Вызов `setShown` запускает повторный рендер компонента.

### Поле ввода

```tsx
<TextField
  value={title}
  onChange={(e) => setTitle(e.target.value)}
/>
```

`value={title}` связывает поле с состоянием. `onChange` срабатывает при вводе. `e` — событие, `e.target` — поле, `e.target.value` — новый текст.

Цепочка выглядит так:

```text
пользователь вводит текст
→ onChange получает событие
→ e.target.value получает строку
→ setTitle записывает строку
→ React заново отображает Tasks
```

Это управляемое поле: его значение контролируется React.

### Кнопка добавления

```tsx
if (title.trim()) {
  setShown([{ title, course: "Домашние задания" }, ...shown]);
  setTitle("");
}
```

1. `trim()` убирает пробелы по краям.
2. Пустая строка не проходит условие.
3. Создаётся объект новой задачи.
4. `[новая задача, ...shown]` создаёт новый массив.
5. `setShown` записывает новый список.
6. React повторно вызывает `Tasks`.
7. Обновлённый `shown` передаётся в `TaskListOverride`.
8. Поле очищается через `setTitle("")`.

`...shown` — spread-оператор. Он раскрывает элементы старого массива внутри нового. Старый массив не изменяется напрямую.

### Передача списка вниз

```tsx
<TaskListOverride tasks={shown} />
```

Слева `tasks` — имя prop, справа `shown` — значение из state. Родитель `Tasks` владеет данными, а дочерний компонент получает их для отображения.

## Компонент `TaskListOverride`

```tsx
function TaskListOverride({ tasks: list }: { tasks: typeof tasks })
```

Компонент получает объект props. `tasks: list` означает: взять свойство `tasks` и внутри функции назвать его `list`.

`{ tasks: typeof tasks }` — тип props для TypeScript. Он проверяет, что компонент получил массив объектов с полями `title` и `course`.

Дальше `list.map(...)` работает так же, как в `TaskList`: каждый объект превращается в `ListItem`.

Главное отличие:

```text
TaskList:
  сам обращается к общему tasks

TaskListOverride:
  получает список извне через prop
```

Поэтому `TaskListOverride` можно использовать и в `Tasks`, где список изменяется, и в `Schedule`, где передаётся исходный массив.

## `Schedule`, `Planner`, `Notifications`

### `Schedule`

Вызывается маршрутом `/schedule`. Возвращает заголовок, пояснение и `TaskListOverride tasks={tasks}`. Здесь повторно используется готовый компонент списка, чтобы не копировать его разметку.

### `Planner`

Вызывается маршрутом `/planner`. Возвращает карточку со статичными пунктами плана. `useState` ему не нужен, потому что пользователь пока не изменяет план.

### `Notifications`

Вызывается маршрутом `/notifications`. Возвращает `List` из двух `ListItem`. `ListItemText` получает основной текст через `primary`, а пояснение через `secondary`.

## `createRoot` в конце файла

```tsx
createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <ThemeProvider theme={theme}>
      <CssBaseline />
      <BrowserRouter>
        <Layout />
      </BrowserRouter>
    </ThemeProvider>
  </StrictMode>,
);
```

`document.getElementById("root")` находит `div` из `index.html`. `!` сообщает TypeScript, что элемент точно существует. `createRoot` создаёт корень React, а `.render` вставляет приложение в найденный контейнер.

Обёртки работают снаружи внутрь:

1. `StrictMode` включает проверки;
2. `ThemeProvider` передаёт тему Material UI;
3. `CssBaseline` задаёт базовые стили;
4. `BrowserRouter` подключает маршрутизацию;
5. `Layout` строит интерфейс.

## Конфигурационные файлы

### `package.json`

Хранит npm-команды и зависимости. `npm run dev` запускает Vite, `npm run build` сначала проверяет TypeScript и затем собирает приложение.

### `package-lock.json`

Автоматически фиксирует точные версии установленных пакетов. Нужен, чтобы у разных разработчиков устанавливалось одинаковое дерево зависимостей.

### `tsconfig.json`

Подключает конфигурации TypeScript для приложения и Node.js.

### `tsconfig.app.json`

Настраивает проверку файлов `src`: JSX, DOM-типы, строгую типизацию и современный JavaScript. `noEmit: true` означает, что TypeScript проверяет код, но не создаёт итоговые JS-файлы.

### `tsconfig.node.json`

Настраивает проверку `vite.config.ts`, который выполняется в среде Node.js, а не в браузере.

### `vite.config.ts`

Подключает `@vitejs/plugin-react`. Благодаря ему Vite умеет обрабатывать React и JSX.

### `index.html`

Содержит `<div id="root"></div>`. `div` — обычный HTML-контейнер. React находит его по `id` и вставляет внутрь всё приложение. Скрипт подключает `src/main.tsx`.

### `node_modules` и `dist`

`node_modules` создаётся командой `npm install` и содержит зависимости. `dist` создаётся командой `npm run build` и содержит готовую production-версию. Оба каталога не редактируют вручную и обычно не отправляют в Git.

## Вопросы на понимание

### Что делает `.map`?

Проходит по массиву, для каждого элемента вызывает функцию и возвращает новый массив результатов. В проекте результатами являются JSX-кнопки или строки списка.

### Что будет, если убрать `key`?

Интерфейс может продолжить работать, но React покажет предупреждение и хуже будет отслеживать элементы динамического списка.

### Что будет, если изменить `shown` напрямую?

Например, `shown.push(...)` изменит массив, но React может не узнать об изменении. Нужно создать новый массив и передать его в `setShown`.

### Кто вызывает `TaskListOverride`?

Его вызывают `Tasks` и `Schedule`. `Tasks` передаёт изменяемый `shown`, а `Schedule` — исходный `tasks`.

### Кто вызывает `TaskList`?

`Dashboard` через JSX `<TaskList />`.

### Кто выбирает `Dashboard` или `Tasks`?

`Routes` выбирает компонент по текущему URL.

### Откуда берётся `title`?

Из `useState`. При вводе новое значение приходит из `e.target.value` и записывается через `setTitle`.

### Куда передаётся `shown`?

Из состояния `Tasks` в prop `tasks` компонента `TaskListOverride`, где prop переименовывается в `list`.

### Почему `Dashboard` не использует `shown`?

У Dashboard нет формы и изменения списка. Он просто показывает исходные демонстрационные данные через `TaskList`.

### Почему после обновления страницы задача исчезает?

Список хранится только в памяти React. Для постоянного хранения нужен backend и база данных, которые относятся к следующей лабораторной.

### Почему React нужен вместе с TypeScript?

React отвечает за интерфейс и его обновление, TypeScript — за проверку типов кода. Это разные задачи.

### Что показать на защите?

Показать все пять экранов, переходы между ними и добавление задания. Затем открыть `main.tsx` и объяснить цепочку `Tasks → shown → prop → TaskListOverride → map → ListItem`.
